08Ask the LLM if the content is what was expected

are_posts_the_same(post1, post2) returns Yes or No.

Present as-is: the simplest LLM-as-judge. Its limits: the judge is itself non-deterministic, and "fundamentally the same" is vague. Calibrate on a few human-labeled pairs; prefer a rubric (slide 10) for anything with more than one criterion.

09Unit test: actual vs expected via the judge

Assert are_posts_the_same(actual, expected) == "Yes".

Present as-is. This is reference-based evaluation; in ADK it corresponds to response_match_score (ROUGE) and final_response_match_v2 (LLM judge).

10Ask the LLM if the content followed the rules

does_post_follow_rules(post): under 100 characters, hashtag present.

Present as-is. This is rubric evaluation: no reference answer, just criteria. Use the model only for judgment calls: len(post) < 100 and post.endswith("#EatAtLuigis") are deterministic and free; the judge is for "on brand."

11Unit test: rule adherence

A compliant post returns "Yes"; a rule-breaking post returns "No".

Present as-is. The negative test is the habit to name: a judge that answers "Yes" to everything passes every test, so always include a case it must reject.

20Model-based metrics

"Fluency, Coherence, Safety, Groundedness, Fulfillment, Summarization Quality; scored 1–5 or 0/1."

Present as-is. These names are current: the vertexai.evaluation module exposes them as MetricPromptTemplateExamples.Pointwise.FLUENCY, .COHERENCE, .GROUNDEDNESS, .SAFETY, .SUMMARIZATION_QUALITY. The one exception is Fulfillment, which does not appear in the current SDK; drop it or replace with INSTRUCTION_FOLLOWING.

The newer client.evals interface (recommended) uses RubricMetric enums (GENERAL_QUALITY, TEXT_QUALITY, etc.) but both interfaces target the same Gen AI evaluation service; neither replaces the other.

Sources: MetricPromptTemplateExamples (SDK source) · evaluation service overview (verified 2026-09-09).

24Evaluating the final response

"Compares the response to a reference · response_match_score, ROUGE, default 0.8."

Present as-is; defaults verified. ROUGE measures word overlap, so it passes a paraphrase that reuses words and fails a correct answer worded differently. For anything beyond short factual replies use final_response_match_v2 (LLM judge), which the deck's list omits.

25Evaluating trajectory and tool use Correction

"Compares expected to actual values of determine_intent, use_tool, review_results, report_generation. Configure tool_trajectory_avg_score."

CorrectionThose four names are not ADK fields. The metric compares the list of tool calls (name and arguments) the agent made against the expected list, per invocation: each matching step scores 1, a mismatch 0, averaged. Default threshold 1.0.
StepExpectedActualScore
1get_order(id=6041)get_order(id=6041)1
2verify_shipment(id=6041)issue_refund(id=6041)0

Average 0.5, below 1.0: the case fails. This is slide 14's regression caught by the metric.

Takeaway: tool_trajectory_avg_score compares tool names and arguments step by step; a skipped verification step is a 0 and fails the case.
Source: eval_metrics.py at v2.7.1 (verified 2026-08-25).

28Test file (JSON example) Correction

A flat list of {"query", "expected_tool_use", "reference"} objects.

CorrectionLegacy schema. It still loads (ADK converts it silently), but the current schema is EvalSet → eval_cases → conversation → invocation, and hand-written files should use it.

Current (EvalSet schema)

{
  "eval_set_id": "dice",
  "eval_cases": [{
    "eval_id": "roll",
    "conversation": [{
      "user_content":   {"parts": [{"text": "roll a die"}]},
      "final_response": {"parts": [{"text": "You rolled a 4."}]},
      "intermediate_data": {"tool_uses": [{"name": "roll_die", "args": {"sides": 6}}]}
    }]
  }]
}

AgentEvaluator.migrate_eval_data_to_new_schema() converts old files. In practice, capture cases in adk web, which writes the current shape.

Takeaway: capture cases in adk web and you get the current schema for free; hand-written files should use it too.
Source: eval_set.py at v2.7.1 (verified 2026-08-25).

33Best practices for evalsets: cover variability

"Simple queries, multi-step workflows, edge cases, ambiguous inputs, failure scenarios; not only happy paths; not static."

Example

The set has 40 cases; all begin with a complete, well-formed request. Production's most common failure is "cancel my order" with two open orders, which is not in the set. Add ambiguous inputs, tool errors, and out-of-scope requests until the set fails the way production does.

Takeaway: an eval set is only as useful as its hardest cases; happy-path sets pass regressions through.

34Best practices for evalsets: version and baseline

"Store in version control · tag with model and prompt versions · track score changes · baseline thresholds · turn incidents into regression tests."

Takeaway: every production failure becomes an eval case, and a new version ships only if its scores are at or above the last accepted version's.

37Use pytest to run your test files Correction

AgentEvaluator.evaluate("module.path", "…/simple_test.test.json") inside a test function.

CorrectionAgentEvaluator.evaluate is async. Called without await in a synchronous test it returns a coroutine that never runs, and the test passes without evaluating anything.
import pytest
from google.adk.evaluation.agent_evaluator import AgentEvaluator

@pytest.mark.asyncio
async def test_agent_behavior():
    await AgentEvaluator.evaluate(
        agent_module="app.agent",
        eval_dataset_file_path_or_dir="tests/eval/simple.test.json",
    )
Takeaway: await the evaluate call; without it the test passes without running.
Source: agent_evaluator.py at v2.7.1 (verified 2026-08-25).

38Integrate ADK Eval into the CI pipeline

"Push → build → deploy to staging → run ADK eval → compare to baseline → gate: promote, or block on regression."

Present as-is; Module 2's eval step seen from the evaluation side. "Compare to baseline" in practice: thresholds in test_config.json, plus the previous run's scores stored so a drop fails the build even when still above the absolute threshold.

Takeaway: the eval run is a build step with an exit code; block the merge, not just the deploy.

39Evaluating production agents

"Log interactions · sample for scoring · monitor tool correctness, latency, cost · detect behavioral drift."

Present as-is. Sample conversations from the Agent Analytics table, score them with the same metrics as CI, and add the failures to the evalset (slide 34). Behavior can change with frozen code when the model version behind an alias changes or the input mix shifts; production sampling is how that is seen.

Takeaway: sample production conversations with the same metrics as CI; frozen code does not mean frozen behavior.
