## General thoughts

- Don't be cute - be clear, concise, elegant
- Don't use shorthand - explain concepts assuming the reader doesn't already know what you're talking about
- Format examples nicely (see m3)
- Focus on evaluation in the context of agent development and operation. The original deck spends a lot of energy on model evaluation which isn't terribly relevant
  - We might say something about doing model eval prior to agent development to select model (or other reasonable use cases for model evaluation as it relates to agent dev)
- I find the source material confusingly organized; we want an easy to follow narrative
- We don't need to talk about non-eval testing in this module
- There's some content about this topic in m2.html which can be informative
- Position (settled 2026-09-13, verified in google-adk 2.9.0 source): the things that look like four evaluation systems are three layers plus a naming accident
  - ADK eval is the local harness: 13 metrics, eight run in-process, five delegate to the Agent Platform evaluation service (`safety_v1`, `response_evaluation_score`, the three `multi_turn_*`)
  - Agent Platform evaluation is the managed scorer plus the production half ADK has no equivalent for: offline runs over historical traces, Online Monitors, loss clustering, the metric registry
  - agents-cli is a third front end over the service, with its own dataset format, adding analyze / compare / synthesize
  - Test file vs. evalset: same schema, same loader. `.test.json` is for `AgentEvaluator`; pytest points it at a path and it discovers files recursively. `.evalset.json` is what `adk web` and `adk eval_set` create and manage, and what `adk eval` takes. The suffix decides which tool finds the file; nothing else differs. Old vs. new format is orthogonal: a legacy fallback that applies to either suffix
- Module boundary, M4 taught first: M4 stands alone. It defines what an eval is, what gets graded, and how a score becomes a pass or fail. Where it touches pipeline placement it points forward to M2 ("Module 2 wires this into CI/CD"). The four-ways-to-run table and the `adk eval` exit-code correction stay in M2; M4 states only the one fact a student needs to act on, that a score is not a gate until something compares it to a threshold, and hands the rest to M2
