## Key sections, in order

### Evaluations in the workflow

- Module 4 covers eval mechanics (criteria, building eval sets). Do not dig into
  that here.
- Do say that evals are as important as unit and integration tests, and show
  where each kind of eval action sits in local development and in integration.
- Shape: one page pulling forward from Module 4 why evaluation matters; one or
  two pages on what you evaluate and the evaluation options you have; then an
  authoritative statement of the best practice for wiring evals into local
  development and CI, followed by common alternative configurations.
- Questions the pages must answer for the developer:
  - Do you run a small set of test cases manually per commit, or after each commit?
  - Do you build a small eval into regular unit testing, or are evals something
    different?
  - What does the local development loop actually look like?
- Questions the pages must answer for the CI/CD system:
  - Is the CI eval set the same one developers use locally? If different, how do
    they differ in scope and size?
  - Where does automatic evaluation run: on push, on pull request?
  - On a dev-branch push or a PR, does it test only that branch, or the merge
    result before the PR merges?

### Deployment targets and tools

- Cover the mechanisms for getting an agent onto Google Cloud:
  - manual Docker build, push to Artifact Registry, `gcloud` deploy to Cloud Run;
  - the same, automated with Cloud Build;
  - `adk deploy` to Cloud Run, GKE, or Agent Runtime;
  - `agents-cli` deploy to any of those targets.
- Differentiate the three targets properly. The source slides are bad at this;
  use other sources. Things that matter:
  - Code execution: Agent Runtime has it built in; Cloud Run has its new
    sandboxes (verify the product name); GKE has GKE Sandbox (gVisor-based,
    verify).
  - Sessions, memory, evaluation, and other services that are simple or
    automatic on Agent Platform but need extra code or work on Cloud Run or GKE.
- Cover the configuration each target needs:
  - Agent Runtime features are often enabled with environment variables.
  - The same features on Cloud Run or GKE may need `get_fast_api_app` switches
    such as `--otel_to_cloud`, or changes to the agent code.
  - Agent Runtime: standard deployment vs. bring-your-own-container, and the
    differences.
  - Agent Runtime config files controlling min/max instances, instance shape,
    and similar.
