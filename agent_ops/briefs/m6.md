## Focus: what is new to FinOps because we're working with agents

- Input tokens dominate because instruction, tool schemas, history, and retrieved chunks are re-sent every turn. Trim those first
- Context caching discounts the prefix and still runs the model. Response caching skips the model and is something you build. Never merge them
- Model choice is a code change, per agent or per request, justified by the eval set
- Cost per conversation comes from event rows, not from billing

### Caching

- Two mechanisms at equal weight, one page each:
  - Implicit caching: automatic, on by default, no storage charge, best effort. Same model, byte-identical prefix, requests close in time, prefix at or above the model minimum. 10% of input price on cached tokens
  - Explicit ADK context caching: `ContextCacheConfig` on the `App`, guaranteed discount for the TTL, storage charge. What is in the fingerprint and the three things that silently reset it
- Response caching as a third, shorter treatment: skips the model on a hit, ADK does not ship one, `before_model_callback` is the hook

### Context compaction

- `EventsCompactionConfig` on the `App`; `token_threshold` and `event_retention_size` set together
- The summarizer is itself a model call: a small fixed cost per compaction buys a smaller prefix on every later turn
- When it pays and when it does not
