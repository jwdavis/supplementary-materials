## Key sections, in order

Note, the guidance below isn't intended to be exhaustive, I'm just calling out things that I see as being critical. You are to build around this, not only this.

Baseline for every claim: google-adk 2.9.0. Where a source says otherwise, the deck follows 2.9.0 and the notes say what changed.
Also: google-genai 2.23.0, google-agents-cli 1.5.0, Model Armor filter v3 (Stable 2026-09-25).

### Model Armor

- Current materials have insufficient (in terms of completeness and clarity) explanation of real-world patterns for model armor consumption within agentic systems
  - What's the best practice? Is it using a plug-in that does pre/post model hooks with model armor api calls and deterministic logic for handling issues?
  - Does inline processing happen with agentic systems? 
  - If so how and when?
  - Do these things differ if in Agent Runtime vs. Cloud Run vs. GKE?
  - Is it only for gemini models?
- Related to that, the current materials seem to focus a lot on using model armor with naked Gemini API calls versus implementing into agentic systems. We want to de-emphasize that. 

### Access

- Securing agent endpoints with workload identity federation slide. It's not at all clear to me what this slide is actually trying to convey. We need to have it be a story that spells out how things work and why you're using it. 
- I feel like we're missing agent identity as a product in Google Cloud, and there should be content on that. 
- I'm not clear what the point and what level of importance there is for SPIFFE, for agent workload identity. 
- It doesn't seem like the slides do a particularly good job of talking about tool access, authentication, and authorization. 
- Again, I think what we want to do is focus not so much on mechanisms, but on scenarios.  How do we control whether the user can access the user interface application that allows them to talk to the agent? How do we control whether or not the client UI is allowed to talk to the API server that wraps the agent? How do we make sure that the agent can perform actions against backend systems, either as itself or as the end user? In which situation would it pick one or the other? Then we want to differentiate whether the approach for each of those scenarios differs between agent runtime, Cloud Run, and GKE.
