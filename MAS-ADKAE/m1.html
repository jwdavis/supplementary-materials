Why AI agents?

Generative AI has moved from answering questions to completing tasks: an agent pairs a model with instructions and tools, then reasons and acts toward a goal across multiple steps.

Customer agents handle external conversations (support, commerce, booking); employee agents boost internal productivity over a company's own processes and knowledge.

Creative agents assist with content and design; data agents query, analyze, and summarize; code agents write, review, and fix software.

Security agents triage alerts and investigate threats faster than humans can read logs.

Every category is built from the same ingredients — models, tools, orchestration, evaluation, deployment — which is exactly the inventory this course teaches with ADK.

Four ways to build agents on Google Cloud

Conversational Agents

External-facing virtual agents for customer channels, with built-in telephony and contact-center integration. Low-code design, deterministic flows where compliance demands them.

Gemini Enterprise

An out-of-the-box assistant and agent platform over your organization's internal knowledge — connect data sources, configure agents, no code required.

Open-source frameworks, or from scratch

Bring LangChain, LangGraph, CrewAI, or hand-written code against the model APIs — and deploy the result to Agent Runtime, which is framework-agnostic.

ADK + Agent Runtime THIS COURSE

Google's open-source, code-first framework for developing, evaluating, and deploying multi-agent systems — paired with a managed runtime built for it.

What is Agent Development Kit? POSITIONING CORRECTED

An open-source, code-first framework for developing, evaluating, and deploying AI agents. The previous deck called it "a client-side, Python SDK" — retire that line.

Multi-language: Python, Go, Java, Kotlin, and TypeScript. Python remains the flagship and is what this course uses.

Since 2.0, ADK describes itself as built on two main classes: Agent (an LLM that reasons and uses tools) and Workflow (a deterministic graph that orchestrates). NEW IN 2.0

Documentation moved to adk.dev (from google.github.io/adk-docs) — multi-language docs, one home.

Releases ship on a roughly bi-weekly cadence; a maintained 1.x line exists for teams not ready to migrate: pip install "google-adk~=1.0".

What does ADK include? The classics

Everything the original slide listed still belongs — all eight carry into 2.x.

Multi-agent systems

Hierarchical agent teams: parents, sub-agents, and LLM-driven transfer between them.

Tools

Prebuilt (Google Search, code execution), custom Python functions, and community integrations (MCP, LangChain).

Evaluation

Assess final responses and step-by-step tool trajectories against saved test cases.

Local Dev UI

adk web — a browser UI for chatting with agents, with debugging and trace views built in.

Callbacks

Hooks before and after agent, model, and tool execution for validation and guardrails.

Sessions, state & memory

Conversation history, working state shared between agents, and long-term memory services.

Artifacts

Named, versioned files (documents, images) that agents and tools save and load.

Managed deployment

Ship the same agent to Agent Runtime, Cloud Run, or GKE with adk deploy.

What does ADK include? The 2.x-era additions (1 of 2)

Badge shows when each capability shipped. Blue = new in 2.x; amber = arrived during 1.x, after the original course was written.

Workflow graph engine 2.0

A Workflow is a directed graph of nodes (agents, functions, tools, nested workflows); edges express sequence, fan-out, and routing. Replaces the deprecated SequentialAgent / ParallelAgent / LoopAgent trio — the headline of 2.0.

Collaboration modes (Task API) 2.0

Agents gain a mode: chat, task (runs to completion, validates output, auto-returns to the parent), or single_turn. The first-class answer to "delegate a bounded job to a sub-agent."

Pause/resume & HITL 1.16 → 2.0

Interrupt an invocation (approval gates, request_input) and resume it later, surviving restarts. Deterministic workflow resume deepened in 2.0.

Plugins 1.x

Cross-cutting behavior packaged once on the App container instead of callback-by-callback: 16 hook points for logging, retries, quota fallbacks, and analytics.

Context caching 1.15

Opt-in Gemini caching of the static request prefix (instruction, tool declarations) — a cost and latency lever for agents with large prompts.

Events compaction 1.16

Automatic LLM summarization of older conversation events, keeping long-running sessions inside the context window.

What does ADK include? The 2.x-era additions (2 of 2)

Skills 1.25 · EXPERIMENTAL

Reusable packets of procedural knowledge in the SKILL.md format, activated on demand via SkillToolset — plus a Google Cloud Skill Registry for sharing across teams.

Environments & computer use 1.27–1.29 SANDBOXES 2.3/2.4

Agents get a workspace: bash and file tools over a local or remote sandbox (E2B in 2.3, Daytona in 2.4, Agent Engine Sandbox), and a browser/GUI toolset via Gemini computer use.

Prompt optimization 1.18–1.20

adk optimize — GEPA-based automatic instruction tuning: iteratively rewrites an agent's instruction using an eval set as the fitness function.

Conformance testing 1.19

adk conformance record captures real runs as YAML test cases; adk conformance test replays them deterministically to catch regressions without live LLM calls.

Teach the vintages honestly: of these ten additions, only the Workflow engine and the Task API are genuinely new in 2.x. The rest shipped during later 1.x — frame them as "new relative to this course," not "new in 2.0."

Where do ADK agents run?

Agent Runtime — the fully managed runtime, part of the Google Cloud Agent Platform (formerly Vertex AI Agent Engine). This is the deployment target Module 4 covers in depth.

Managed sessions, memory, and a console UI (Playground, Traces, Sessions, Evaluation tabs) have now shipped — the old "coming soon" claims are stale.

Anywhere containers run: Cloud Run and GKE are first-class targets via adk deploy cloud_run and adk deploy gke — or run locally during development with adk web.

Tell students explicitly: the marketing name and the API surface disagree. The CLI command is still adk deploy agent_engine, and deployed resource names still read .../reasoningEngines/NNNN. Students will hit both old names the first time they deploy.
